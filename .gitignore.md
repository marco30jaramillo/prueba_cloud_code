# 📋 Explicación de .gitignore

## ¿Por qué algunos archivos no se suben a Git?

### 🔴 **NUNCA SUBIR** (Seguridad)

#### `.env` - Variables de entorno
```
Contiene: JWT_SECRET, credenciales
Riesgo: Alguien podría acceder a tu servidor
```

#### `users.csv` - Base de datos de usuarios
```
Contiene: Datos personales, contraseñas cifradas
Riesgo: Exposición de datos de usuarios
```

#### `tokens_granted.csv` y `tokens_revoked.csv`
```
Contiene: Tokens JWT activos de usuarios
Riesgo: Alguien podría hijackear sesiones
```

#### `node_modules/` - Dependencias
```
Tamaño: ~100-500 MB
Razón: Se instalan con `npm install`
```

### 🟡 **IGNORAR** (Desarrollo)

#### `*.log` - Archivos de logs
```
Razón: Se generan automáticamente durante ejecución
```

#### `.DS_Store` - Archivos del sistema macOS
```
Razón: Archivos internos del OS, no relevantes
```

#### `.vscode/`, `.idea/` - Configuración de IDEs
```
Razón: Cada dev usa su propia configuración
```

#### `dist/`, `build/` - Archivos compilados
```
Razón: Se generan automáticamente
```

## ✅ **SÍ SUBIR** (Código y documentación)

```
✅ src/               - Tu código
✅ package.json       - Dependencias (sin versiones exactas)
✅ CLAUDE.md          - Documentación técnica
✅ README_REPO.md     - Guía para usuarios
✅ API_*.md           - Documentación de API
✅ .env.example       - Ejemplo de configuración (sin valores)
✅ .gitignore         - Este archivo
```

## 📝 Workflow Correcto

### 1. Antes de hacer commit
```bash
# Ver qué archivos vas a subir
git status

# NUNCA deberías ver:
#   users.csv
#   .env (sin .example)
#   tokens_*.csv
#   node_modules/
```

### 2. Actualizar .env después de clonar
```bash
# Cuando clones el repo:
cp .env.example .env

# Luego edita .env con tus valores reales
# Pero NO hagas commit de .env
```

### 3. Compartir credenciales de forma segura
```bash
# NO en Git:
❌ git push  # NO hagas esto si .env está incluido

# SÍ en otros canales:
✅ Email privado
✅ 1Password / LastPass
✅ Discord privado
✅ Reunión privada
```

## 🛡️ Checklist de Seguridad

Antes de hacer `git push`:

- [ ] ¿`.env` está en `.gitignore`? 
- [ ] ¿Existe `.env.example` con valores dummy?
- [ ] ¿No hay `users.csv` en los archivos a subir?
- [ ] ¿No hay `tokens_*.csv` en los archivos a subir?
- [ ] ¿No hay `node_modules/` en los archivos a subir?
- [ ] ¿No hay archivos `.log` en los archivos a subir?

Verifica con:
```bash
git status
```

---

## 🔧 Recuperar si Subiste por Accidente

Si accidentalmente subiste un archivo sensible:

```bash
# 1. Remover del historio de Git (pero no del disco)
git rm --cached .env
git rm --cached users.csv

# 2. Hacer commit
git commit -m "Remove sensitive files"

# 3. Push
git push

# 4. Cambiar credenciales en producción (importante!)
# Porque ya fueron comprometidas
```
